# Spec Delta

## Purpose

定义元数据、业务知识与智能体知识三类知识库的内容模型、文档来源、隔离边界、入库生命周期与原文引用，使知识可持久化、可追溯、可重试，并能安全地服务检索。

## ADDED Requirements

### Requirement: 三类知识库分离

系统 SHALL 提供元数据知识库、业务知识库与智能体知识库三类知识集合，各自拥有独立的条目模型与检索范围；同一数据源或 Agent 的知识 MUST NOT 跨类型混入。

#### Scenario: 分库存储

- **WHEN** 管理员分别写入一条元数据知识、一条业务知识和一条智能体知识
- **THEN** 三条知识分别归属于对应类型，按类型检索时只返回本类型条目

#### Scenario: 类型隔离

- **WHEN** 检索业务知识
- **THEN** 结果中不出现元数据知识或智能体知识的条目

### Requirement: 知识归属与维度隔离

每条知识 SHALL 明确归属于一个知识类型、一个数据源（或全局）以及可选的 Agent；检索 MUST 只在调用者可见的维度内进行。元数据知识按数据源隔离，业务知识可按数据源或全局共享，智能体知识按 Agent 隔离。

#### Scenario: 不同数据源的元数据不串

- **WHEN** 两个数据源各自维护元数据知识并发起检索
- **THEN** 每个数据源的检索只返回本数据源的表与字段

#### Scenario: Agent 知识不跨 Agent

- **WHEN** 两个 Agent 各自配置了智能体知识
- **THEN** 每个 Agent 的检索只返回自己的智能体知识

### Requirement: 元数据知识内容与同步

元数据知识 SHALL 覆盖库表、字段、主键、外键和字段语义描述，并能与数据源实时内省结果对齐；内省结果变化后 MUST 支持重新同步，且不得产生重复条目或重复向量。

#### Scenario: 表结构同步

- **WHEN** 管理员对某数据源执行元数据同步
- **THEN** 该数据源的表、字段、主键与外键被写入元数据知识库，并进入待 embedding 状态

#### Scenario: 结构变更后重同步

- **WHEN** 数据源新增一列后再次同步
- **THEN** 对应知识条目被更新而不是重复新增，旧向量被替换

### Requirement: 业务知识与字段级语义映射

业务知识 SHALL 支持业务术语、统计口径与指标定义；系统 MUST 支持维护业务俗语到表或字段的映射，并在检索时用映射扩展查询表达。

#### Scenario: 俗语映射

- **WHEN** 用户提问使用「挂科」而物理列名为 `score < 60`
- **THEN** 检索使用已维护的俗语映射扩展查询，并召回相关表与字段

#### Scenario: 未映射俗语

- **WHEN** 提问中的俗语没有对应映射
- **THEN** 系统按原始问题继续检索，不报错也不编造映射

### Requirement: 智能体知识的作用域

智能体知识 SHALL 存储 Agent 专属的提示、工具说明与领域规则，并支持以文档形式提供；检索结果 MUST 只注入到对应 Agent 的上下文，不得进入其他 Agent 或确定性流水线的提示。

#### Scenario: Agent 专属注入

- **WHEN** 某 Agent 处理请求并命中自己的智能体知识
- **THEN** 命中内容只出现在该 Agent 的上下文

#### Scenario: 无匹配不注入

- **WHEN** 某 Agent 没有命中的智能体知识
- **THEN** 不注入任何智能体知识，也不使用其他 Agent 的知识补位

### Requirement: 多格式文档来源

系统 SHALL 接受文件上传与网页 URL 两种知识来源，并支持 PDF、Word、PPT、Excel、图片、纯文本、Markdown、CSV 与 HTML 格式。不支持的格式、超出大小或页数限制的文件 MUST 被明确拒绝并说明原因，不得部分入库。

#### Scenario: 上传复杂文档

- **WHEN** 管理员上传一个包含图文混排的 PDF
- **THEN** 系统接受该文件并进入解析流程，原文被持久化保存

#### Scenario: 网页导入

- **WHEN** 管理员提交一个网页 URL
- **THEN** 系统抓取该页面内容并作为知识来源入库，同时保存抓取快照

#### Scenario: 超限文件

- **WHEN** 上传的文件超出配置的大小或页数上限
- **THEN** 系统拒绝该文件并返回可读原因，知识库中不产生该条目的任何片段

### Requirement: 可插拔文档解析

系统 SHALL 以可替换的解析策略处理文档：文本类文档 MUST 产出纯文本与字符区间，版面类文档（PDF、图片、复杂版式）MUST 产出页码与归一化到 0–1000 的坐标框。解析引擎及其版本 MUST 记录在文档上，以便追溯与重新解析。

#### Scenario: 文本类文档解析

- **WHEN** 解析一个 Word 或 Markdown 文档
- **THEN** 系统产出纯文本，并为每个片段记录其在纯文本中的字符区间

#### Scenario: 版面类文档解析

- **WHEN** 解析一个 PDF 或图片
- **THEN** 系统为每个片段记录页码（从 1 开始）与归一化坐标框

#### Scenario: 切换解析引擎

- **WHEN** 管理员对同一文档改用另一种解析引擎重新解析
- **THEN** 文档记录新的引擎与版本，旧片段与向量被替换而非并存

### Requirement: 原文与派生内容持久化

系统 SHALL 将原文对象与解析产物（结构化内容、文本快照、可选的页面渲染图）持久化到对象存储，知识库中只保存对象键。服务重启或容器重建后原文 MUST 仍可取回；删除知识条目时 MUST 一并清理其原文与派生对象。

#### Scenario: 重启后取回原文

- **WHEN** 服务重启后打开一条此前入库的文档引用
- **THEN** 仍能取回原文并定位到相同位置

#### Scenario: 删除清理

- **WHEN** 管理员删除一条文档型知识
- **THEN** 该文档的原文、解析产物与向量一并删除，引用不再可打开

#### Scenario: 对象存储不可用

- **WHEN** 对象存储不可用时读取原文
- **THEN** 系统返回明确的不可用错误，不返回其他文档的内容

### Requirement: 原文引用元数据

每个可召回的片段 SHALL 携带引用元数据，至少包含：文档标识、文档名、页码或字符区间、原文引用文本，以及版面类文档的坐标框。缺少引用元数据的片段 MUST NOT 被标记为就绪，也不得参与检索。

#### Scenario: 片段带引用

- **WHEN** 一条文档型知识完成解析并进入就绪状态
- **THEN** 它的每个片段都能定位到具体文档与页码（或字符区间）以及原文引用文本

#### Scenario: 引用缺失

- **WHEN** 解析结果无法为某片段确定位置信息
- **THEN** 该片段不被写入就绪集合，并在文档上记录可读的失败原因

### Requirement: 网页快照与引用稳定性

网页来源的知识 SHALL 保存抓取时的内容快照，引用 MUST 指向快照而不是实时网页；网页后续变化 MUST NOT 改变既有引用的内容。

#### Scenario: 网页更新后引用不变

- **WHEN** 已入库的网页在源站被修改后再次查看引用
- **THEN** 预览展示的是入库时的快照内容，并标注抓取时间

### Requirement: 入库生命周期与状态机

知识写入 SHALL 先持久化知识记录与原文，再在事务提交后异步执行解析、分块与 embedding；每条知识的状态 MUST 可观测为待处理、解析中、处理中、就绪或失败，失败 MUST 保留可读原因、失败阶段并支持重试。

#### Scenario: 提交后异步处理

- **WHEN** 一条知识写入成功并提交事务
- **THEN** 系统异步执行解析与 embedding，写入请求不被阻塞

#### Scenario: 解析失败可重试

- **WHEN** 某文档解析失败
- **THEN** 该条目状态为失败，记录失败阶段与原因，管理员可重试且重试成功后状态变为就绪

#### Scenario: embedding 失败可重试

- **WHEN** 某条知识的向量生成失败
- **THEN** 该条目状态为失败并记录原因，管理员可触发重试且重试成功后状态变为就绪

#### Scenario: 状态可查询

- **WHEN** 管理员查看知识列表
- **THEN** 每条知识显示当前状态、解析引擎与最近一次失败原因（如有）

### Requirement: 幂等写入与删除清理

同一知识条目的重复写入 SHALL 幂等替换旧版本，不得产生重复向量；删除知识条目 MUST 同时移除其向量、分块与原文对象，不留孤儿数据。

#### Scenario: 重复入库

- **WHEN** 同一数据源的同一条目被再次写入
- **THEN** 旧内容与旧向量被替换，条目总数不增加

#### Scenario: 删除清理

- **WHEN** 管理员删除一条知识
- **THEN** 该条目的记录、分块、向量与原文一并删除，检索不再命中

### Requirement: pgvector 持久化与故障语义

知识与向量 SHALL 持久化在 PostgreSQL + pgvector 中，服务重启后 MUST 保留；向量库与应用库 MUST 相互独立。向量库不可用时，知识检索 MUST 返回可读错误，不得静默降级为内存存储或返回伪造结果。

#### Scenario: 重启后保留

- **WHEN** 服务重启后再次检索已入库的知识
- **THEN** 仍能命中重启前写入的条目

#### Scenario: 向量库不可用

- **WHEN** PostgreSQL + pgvector 连接失败时调用知识检索接口
- **THEN** 接口返回明确的不可用错误，不返回内存中的临时结果

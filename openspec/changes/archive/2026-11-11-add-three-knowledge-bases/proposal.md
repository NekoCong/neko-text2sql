# Proposal

## Why

当前知识库是内存态、单一命名空间、进程重启即丢失，元数据、业务知识与智能体知识混在一起；Schema 检索只对「表名 + 列名」做 embedding，无法承载业务俗语、字段级语义映射和 Agent 私有知识。参照 DataAgent 的三库分离模型，把知识持久化到 pgvector，才能让检索可运营、可追溯，并支撑后续的 Graph/Agent 改造。

同时，智能体知识的真实载体是文档而不是纯文本：PPT、Word、Excel、图片和网页 URL 无法只靠「一段字符串」表达，检索命中后也需要能回到原文核对。因此本次一并补齐文档解析、原文持久化与原文引用。

## What Changes

- 新增三类知识库：**元数据知识库**（库表/字段/外键）、**业务知识库**（业务术语、口径、指标）、**智能体知识库**（Agent 提示、工具说明、领域规则、参考文档）；三类分开建库、统一管理。
- 用 **PostgreSQL + pgvector** 持久化知识记录与向量；新增独立容器，应用库继续使用 MySQL + R2DBC。
- 知识入库生命周期：写入知识记录与原文 → 发布领域事件 → 事务提交后异步执行「解析 → 分块 → embedding」→ 状态机（`PENDING` / `PARSING` / `EMBEDDING` / `READY` / `FAILED`）→ 失败按阶段可重试、可定位。
- 字段级语义模型：维护业务俗语 ↔ 表/字段的映射，解决口语与物理列名对不上的问题。
- 检索链路：查询改写 → 双路召回（业务知识 + 智能体知识）→ 表级召回 → 列跟随表补齐 → 外键补一跳 → LLM 精选最终表集合；异常时回退全量 schema。
- **多格式文档入库**：支持上传 PDF / Word / PPT / Excel / 图片 / 文本 / Markdown / CSV / HTML，以及网页 URL；解析器可插拔，文本类文档走轻量文本抽取，PDF、图片与复杂版式走版面解析并产出页码与坐标。
- **原文持久化**：原文与解析产物存入对象存储（MinIO），知识库只保存对象键；服务重启、容器重建后原文仍可取回。
- **原文引用**：每个可召回片段携带引用元数据（文档、页码、归一化坐标或字符区间、原文引用文本）；前端以角标展示，点击打开原文预览并高亮命中位置。
- 元数据检索接入现有 `SchemaProvider`，增强/替换内存版 `RagSchemaProvider`，流水线接口保持不变。
- 新增知识库管理 API 与前端页面：三类分栏、条目/文档 CRUD、文档上传与 URL 导入、解析状态、检索调试、状态查看与失败重试。
- 权限：检索结果按调用者的数据源授权与表级白名单裁剪，不得通过知识检索泄露范围外表/列；原文预览同样受知识范围约束。
- 基础设施统一使用**华为云 SWR 镜像**（`swr.cn-north-4.myhuaweicloud.com/ddn-k8s/...`），规避国内拉取 Docker Hub 失败。
- **非目标**：不引入 Spring AI Alibaba Graph；不改变现有「一次生成 + 校验 + 执行」的 SQL 生成策略（候选生成/自修复另开 change）；不把应用库迁移到 PostgreSQL；v1 不做 Office → PDF 的版面转换（Office 文档的引用以字符区间 + 文本快照呈现）。

## Capabilities

### New Capabilities

- `knowledge-base/ingestion`: 三类知识库的数据模型与分库隔离、pgvector 持久化、入库与异步 embedding 生命周期、字段级语义映射、多格式文档解析、原文对象存储与引用元数据。
- `knowledge-base/retrieval`: 查询改写、双路召回、表/列召回与补齐、外键扩展、LLM 选表、调用者范围裁剪、引用回传与失败回退。

### Modified Capabilities

- `data-permission`: 表级白名单的作用面从「SQL 执行 / 元数据查询 / schema 提示」扩展到「知识检索与原文引用」，检索结果与预览不得泄露范围外表与列。
- `ui/screens`: 新增知识库管理页面与原文引用预览交互（角标、分页预览、高亮定位），纳入数据管理类页面的导航、布局、状态与权限规范。

## Impact

- **后端**：`knowledge` 包新增知识模型、文档模型、pgvector 仓储与检索服务；新增解析器抽象与两种实现（文本抽取、版面解析）、对象存储客户端；`KnowledgeController` 扩展为三类知识库、文档上传与检索调试接口；`RagSchemaProvider` 改为基于元数据知识库；`application.yml` 新增 pgvector、MinIO、解析器与检索参数；`pom.xml` 增加 PostgreSQL/pgvector、对象存储、文档解析依赖。
- **前端**：新增知识库管理视图、原文预览组件、路由与导航入口、对应 API 模块；引入 PDF 渲染依赖。
- **基础设施**：`docker-compose.yml` 增加 PostgreSQL + pgvector 与 MinIO 服务（华为云镜像）及初始化脚本；可选增加对象存储初始化任务。
- **数据**：新增知识库表结构（知识条目、文档、分块、向量、语义映射、入库状态、引用字段），以及对象存储中的原文与派生内容。
- **外部依赖**：版面解析依赖 MinerU 云 API（需 Token、有配额与文件大小限制），需可关闭与可回退；文本抽取在本地完成，无外部依赖。
- **测试**：知识模型/生命周期/检索/引用映射单元测试；pgvector 集成测试（可通过 profile 或容器启用）；对象存储与解析器以接口替身测试，`mvn test` 不依赖 Docker 与外部 API。

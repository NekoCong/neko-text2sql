# Spec Delta

## ADDED Requirements

### Requirement: Agent 数据范围上下文

系统 SHALL 在构建对话 Agent 时注入调用者的数据范围说明，内容包括角色、是否受限以及行级范围的可读描述。该说明 MUST 来自服务端解析的调用者身份，不得由模型输出或用户输入决定。

#### Scenario: 学生会话

- **WHEN** 学生发起 Agent 提问
- **THEN** Agent 的系统上下文包含"仅本人"范围说明及该学生自身的标识，模型在生成回答前即可看到该限制

#### Scenario: 管理员会话

- **WHEN** 管理员发起 Agent 提问
- **THEN** Agent 的系统上下文标明数据范围不受限

#### Scenario: 会话不串号

- **WHEN** 两个不同用户分别与 Agent 对话
- **THEN** 每次构建的 Agent 只包含该次调用者自己的范围说明

### Requirement: 范围受限时的回答语义

非管理员经 Agent 得到的数据只覆盖其数据范围。当问题需要范围外数据或查询结果为空时，回答 MUST 明确说明结果受当前账号数据范围限制，并 MUST NOT 将其表述为"数据库中没有""不存在"或等价断言。

#### Scenario: 学生询问跨班成绩

- **WHEN** 学生询问"1 班和 2 班的数学平均分"，而结果只包含本人范围
- **THEN** 回答给出范围内的结果，并说明 2 班数据不可见是当前账号的数据范围限制，而不是数据库缺少 2 班

#### Scenario: 空结果

- **WHEN** 受限账号的查询返回 0 行
- **THEN** 回答说明"当前数据范围内没有可见记录"，不得推断数据库中不存在对应数据

#### Scenario: 辅导员询问非管理班级

- **WHEN** 辅导员询问其管理范围之外班级的统计
- **THEN** 回答说明只能覆盖其所管理班级，不对范围外班级的数据是否存在下结论

### Requirement: 不得探测范围外存在性

Agent MUST NOT 为判断范围外数据是否存在而发起额外查询（如计数、存在性检查或按范围外标识过滤的探测查询），回答也 MUST NOT 断言范围外对象存在或不存在。

#### Scenario: 要求确认班级是否存在

- **WHEN** 学生要求确认"2 班是否存在"
- **THEN** 回答只说明当前账号无权查看该范围，不给出存在性结论，也不额外执行探测查询

### Requirement: 范围说明不泄露范围外对象

注入 Agent 的数据范围说明与工具返回的范围元数据 MUST 只包含调用者自身范围信息，MUST NOT 出现范围外的表名、班级名称或 ID、学号等可识别对象。表与列的可见性仍按表级白名单裁剪。

#### Scenario: 学生范围说明

- **WHEN** 系统为学生构建范围说明
- **THEN** 说明中只出现该学生自己的学号与所属班级，不出现其他班级或其他学生

#### Scenario: 工具元数据

- **WHEN** Agent 调用表结构工具
- **THEN** 返回的表与列仍只包含调用者白名单内的对象

### Requirement: 确定性范围澄清兜底

对数据范围受限的账号，若最终回答仍出现"不存在""没有数据""数据库中只有"等否定断言，系统 SHALL 在返回前追加一段数据范围澄清。该澄清 MUST NOT 声称范围外数据存在，也 MUST NOT 出现在管理员的无限制回答中。

#### Scenario: 否定断言被纠正

- **WHEN** 受限账号的回答中出现"2 班不存在"一类表述
- **THEN** 前端收到的最终回答包含数据范围澄清，说明该结论可能只是权限范围导致

#### Scenario: 管理员不追加

- **WHEN** 管理员提出同类问题
- **THEN** 回答不添加范围免责声明或澄清段落

#### Scenario: 已含澄清不重复

- **WHEN** 回答已经明确说明数据范围限制
- **THEN** 系统不再追加重复的澄清段落

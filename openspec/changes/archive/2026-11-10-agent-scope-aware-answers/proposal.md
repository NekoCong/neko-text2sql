# Proposal

## Why

Agent 模式的权限**执行**是对的：工具从运行时上下文拿到 `DataScope`，生成的 SQL 会被强制重写。但模型**不知道**调用者的数据范围，于是把"被权限过滤掉的空结果"解释成"数据库里没有这些数据"。学生李娜问"1 班和 2 班的数学平均分"，回答变成"数据库只有 1 班，2 班没有数据"——这与事实不符，也会让用户误以为数据缺失而不是权限受限。

确定性流水线已经在回答里追加数据范围说明（`scopedExplanation`），Agent 路径没有对应机制；现有 `data-permission` 规范的"越界问题的回答语义"也没有约束 Agent 的自然语言回答。

## What Changes

- 抽出**统一的数据范围描述**（角色、是否受限、行级范围的可读说明），同时供流水线提示词与 Agent 使用；不包含范围外表名、班级或学号。
- Agent 的系统提示词按请求注入该描述，并明确规则：
  - 非管理员的结果只覆盖该范围；空结果或缺少某个实体时，**不得**断言"不存在/没有数据"，必须说明是当前账号的数据范围限制。
  - 不得为确认范围外数据是否存在而额外探测（不查 count/存在性），避免泄露存在性。
  - 管理员不受限，不添加多余的免责声明。
- `query_database` 工具返回增加机器可读的 `dataScope` 块（是否受限、角色、说明），让模型在组织回答时有据可依。
- 增加确定性兜底：受限账号的回答若出现"不存在/没有数据/数据库中只有"等否定断言，追加一段标准的数据范围说明（不声称范围外数据存在）。
- 补充测试与文档，覆盖学生/辅导员/管理员三种范围。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `data-permission`: 将"越界问题的回答语义"扩展到 Agent 路径——要求 Agent 的回答披露数据范围、不得把权限过滤误述为数据缺失，并禁止探测范围外数据的存在性。

## Impact

- 代码：`Text2SqlAgentService`、`HarnessAgentFactory`、`SqlTools`、`PromptCatalog`、`Text2SqlPipelineService`（复用范围描述）；新增数据范围描述与回答兜底组件。
- 提示词：`resources/prompts/agent-system.md` 增加数据范围占位符与回答规则。
- 契约：`query_database` 的工具返回 JSON 增加 `dataScope` 字段（仅模型可见，前端 API 不变）。
- 数据/接口：无数据库变更，无新增 HTTP 接口，不影响现有前端事件契约。
- 测试：新增范围描述、提示词注入、工具返回、回答兜底的单元测试；现有 Agent/流水线测试保持通过。

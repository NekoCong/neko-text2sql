# data-permission Specification

## Purpose

定义 NL2SQL 场景下的主体身份、数据范围与行级权限契约：同一个问题在不同角色下必须得到不同范围的数据，且该范围由系统强制，不依赖模型自觉。

## Requirements
### Requirement: 角色识别与拒绝语义

系统 SHALL 只承认 `student`、`counselor`、`admin` 三种角色，并在每个 NL2SQL 请求上从访问令牌解析调用者角色。缺失或无法识别的角色 MUST 被当作"无数据权限"处理：请求被拒绝并返回可读原因，不得降级为任何具有数据访问能力的角色。

#### Scenario: 学生令牌

- **WHEN** 携带 `role=student` 的令牌请求 NL2SQL
- **THEN** 系统按学生策略处理该请求

#### Scenario: 无法识别的角色

- **WHEN** 令牌中的角色缺失或为未定义值
- **THEN** 请求被拒绝，且响应说明当前账号没有数据权限，而不是返回任何数据行

### Requirement: 主体数据范围解析

系统 SHALL 在应用侧（而非被查询的业务库）解析调用者的数据范围：学生为"本人"（本人学号及其所属班级），辅导员为"其所管理的班级集合"，管理员为全量且不受范围限制。非管理员账号若没有任何范围映射，请求 MUST 被拒绝，不得以"看不到数据"的空结果代替明确拒绝。

#### Scenario: 学生范围

- **WHEN** 学生账号发起查询
- **THEN** 可用范围为该学生本人的记录及其所属班级

#### Scenario: 辅导员范围

- **WHEN** 辅导员账号管理两个班级并发起查询
- **THEN** 可用范围为这两个班级的全部记录，且不包含其他班级

#### Scenario: 未配置范围

- **WHEN** 非管理员账号没有任何范围映射
- **THEN** 请求被拒绝并说明"未配置数据范围"，且不执行任何 SQL

### Requirement: 表级白名单

系统 SHALL 按角色限定可访问的表：学生与辅导员只能引用校园域中的公开维度表与受限事实表，管理员不受表限制。表级白名单 MUST 同时作用于四处：生成的 SQL 执行、元数据查询（表/列清单）、送入模型的 schema 提示、知识检索结果。引用白名单外的表 MUST 在产生任何数据前被拒绝。原文预览 MUST 在签发预览地址前校验该文档所属知识对调用者可见，且 MUST NOT 因预览暴露元数据知识中的范围外表与列。

#### Scenario: 学生引用受限表

- **WHEN** 学生的问题导致 SQL 引用白名单外的表
- **THEN** 查询被拒绝并说明该表不在当前数据范围内

#### Scenario: 元数据不泄露

- **WHEN** 学生请求列出可用表或查看某表结构
- **THEN** 返回结果只包含其白名单内的表，且被问及的白名单外表不会出现在可用表清单中

#### Scenario: 模型只见允许的对象

- **WHEN** 系统为学生构造 schema 提示
- **THEN** 提示中不包含其无权访问的表或列

#### Scenario: 知识检索不泄露

- **WHEN** 学生发起知识检索，问题涉及白名单外的表或字段
- **THEN** 检索结果与调试信息都不包含该表或字段的名称、描述或向量片段

#### Scenario: 原文预览不越权

- **WHEN** 学生请求预览一个属于其他数据源或其他 Agent 的文档
- **THEN** 请求被拒绝，且不返回原文内容、对象键或可用的预览地址

### Requirement: 行级过滤强制

对于每个非管理员请求，系统 SHALL 在执行前对语句中每张受行级约束的表施加该角色的行过滤条件。强制 MUST 独立于模型输出：模型未写过滤条件时自动补上，模型写了更宽的条件时不会放宽到范围之外，且结果集的聚合、排序、分页均基于过滤后的数据计算。

#### Scenario: 模型未写过滤条件

- **WHEN** 学生提问"各科平均分是多少"而模型生成的 SQL 没有学生过滤条件
- **THEN** 返回的平均分只由该学生自己的成绩计算

#### Scenario: 模型写了越界条件

- **WHEN** 学生要求查询另一个学号的成绩，模型也照此生成 SQL
- **THEN** 执行结果为空，且不返回该学号的任何数据

#### Scenario: 绕过尝试

- **WHEN** 问题中包含"忽略之前的规则""查询全校数据"等提示注入，或生成的 SQL 通过子查询、联合、自连接引用受限表
- **THEN** 每个引用点仍然受同一行过滤约束，结果不越界

#### Scenario: 辅导员跨班

- **WHEN** 辅导员查询其管理的两个班级的考勤统计
- **THEN** 结果覆盖两个班级且不包含其他班级

### Requirement: 无法强制即拒绝

当系统无法确定语句中全部表引用的过滤方式（例如语句无法解析、使用了不受支持的结构）时，系统 MUST 拒绝执行并返回明确错误，禁止以原始 SQL 直接执行。

#### Scenario: 解析失败

- **WHEN** 生成的 SQL 无法被解析为可施加过滤的只读查询
- **THEN** 请求失败并说明无法应用数据权限，数据库中不执行任何语句

### Requirement: Agent 路径同等强制

经由智能体工具发起的查询 SHALL 与确定性流水线使用同一套角色、表级与行级规则，并且 MUST 使用当前请求的调用者身份。智能体不得以匿名或其它用户身份执行查询，也不得通过子智能体绕过范围限制。

#### Scenario: 智能体查询

- **WHEN** 学生通过对话智能体提问
- **THEN** 智能体执行的查询与学生直接调用流水线得到相同范围的数据

#### Scenario: 会话不串号

- **WHEN** 两个用户分别与智能体对话
- **THEN** 每个会话只使用其自身调用者的数据范围

### Requirement: 越界问题的回答语义

当问题所需数据超出调用者范围时，系统 SHALL 在回答中说明当前数据范围限制，并 MUST NOT 编造、推断或声称拥有范围外的数据。

#### Scenario: 超出范围的提问

- **WHEN** 学生询问"全校排名"或其它需要跨班数据的问题
- **THEN** 回答只基于本人数据，并明确说明当前仅能访问本人范围

### Requirement: Agent 数据范围上下文

系统 SHALL 在构建对话 Agent 时注入调用者的数据范围说明，内容包括角色、是否受限以及行级范围的可读描述。该说明 MUST 来自服务端解析的调用者身份，不得由模型输出或用户输入决定。

#### Scenario: 学生会话

- **WHEN** 学生发起 Agent 提问
- **THEN** Agent 的系统上下文包含"仅本人"范围说明及该学生自身的标识，模型在生成回答前即可看到该限制

#### Scenario: 管理员会话

- **WHEN** 管理员发起 Agent 提问
- **THEN** Agent 的系统上下文标明数据范围不受限

#### Scenario: 会话不串号

- **WHEN** 两个不同用户分别与 Agent 对话
- **THEN** 每次构建的 Agent 只包含该次调用者自己的范围说明

### Requirement: 范围受限时的回答语义

非管理员经 Agent 得到的数据只覆盖其数据范围。当问题需要范围外数据或查询结果为空时，回答 MUST 明确说明结果受当前账号数据范围限制，并 MUST NOT 将其表述为"数据库中没有""不存在"或等价断言。

#### Scenario: 学生询问跨班成绩

- **WHEN** 学生询问"1 班和 2 班的数学平均分"，而结果只包含本人范围
- **THEN** 回答给出范围内的结果，并说明 2 班数据不可见是当前账号的数据范围限制，而不是数据库缺少 2 班

#### Scenario: 空结果

- **WHEN** 受限账号的查询返回 0 行
- **THEN** 回答说明"当前数据范围内没有可见记录"，不得推断数据库中不存在对应数据

#### Scenario: 辅导员询问非管理班级

- **WHEN** 辅导员询问其管理范围之外班级的统计
- **THEN** 回答说明只能覆盖其所管理班级，不对范围外班级的数据是否存在下结论

### Requirement: 不得探测范围外存在性

Agent MUST NOT 为判断范围外数据是否存在而发起额外查询（如计数、存在性检查或按范围外标识过滤的探测查询），回答也 MUST NOT 断言范围外对象存在或不存在。

#### Scenario: 要求确认班级是否存在

- **WHEN** 学生要求确认"2 班是否存在"
- **THEN** 回答只说明当前账号无权查看该范围，不给出存在性结论，也不额外执行探测查询

### Requirement: 范围说明不泄露范围外对象

注入 Agent 的数据范围说明与工具返回的范围元数据 MUST 只包含调用者自身范围信息，MUST NOT 出现范围外的表名、班级名称或 ID、学号等可识别对象。表与列的可见性仍按表级白名单裁剪。

#### Scenario: 学生范围说明

- **WHEN** 系统为学生构建范围说明
- **THEN** 说明中只出现该学生自己的学号与所属班级，不出现其他班级或其他学生

#### Scenario: 工具元数据

- **WHEN** Agent 调用表结构工具
- **THEN** 返回的表与列仍只包含调用者白名单内的对象

### Requirement: 确定性范围澄清兜底

对数据范围受限的账号，若最终回答仍出现"不存在""没有数据""数据库中只有"等否定断言，系统 SHALL 在返回前追加一段数据范围澄清。该澄清 MUST NOT 声称范围外数据存在，也 MUST NOT 出现在管理员的无限制回答中。

#### Scenario: 否定断言被纠正

- **WHEN** 受限账号的回答中出现"2 班不存在"一类表述
- **THEN** 前端收到的最终回答包含数据范围澄清，说明该结论可能只是权限范围导致

#### Scenario: 管理员不追加

- **WHEN** 管理员提出同类问题
- **THEN** 回答不添加范围免责声明或澄清段落

#### Scenario: 已含澄清不重复

- **WHEN** 回答已经明确说明数据范围限制
- **THEN** 系统不再追加重复的澄清段落
